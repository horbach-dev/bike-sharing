# Архитектура

## Клиент: React + Vite

Клиент собирается как SPA, поэтому один и тот же URL можно открыть в обычном браузере и Telegram WebView. Telegram SDK подключён на странице, а TelegramProvider мягко включает интеграцию только при наличии window.Telegram.WebApp. Проверку подписи initData нужно реализовать на API до включения Telegram-аутентификации.

Frontend использует FSD. Текущие слои: app, pages, widgets, shared. entities и features появятся, когда у них будет реальная предметная ответственность; пустые слои пока не создаются. Межслойные импорты идут через публичные index.ts.

## Бренд и интерфейс

Рабочее название демо — Scoot Nha Trang. Основной цвет — морской teal, дополнительные — коралловый и песочный. Пользовательская страница mobile-first; админка рассчитана на широкий экран и адаптируется для телефона. Изображения и знак бренда лежат в `apps/web/public/brand/`.

## UI

Shadcn/ui используется как исходная база компонентов: компоненты хранятся и развиваются в проекте, а не подключаются как закрытая библиотека. Общие примитивы доступны админке и пользовательским страницам. Предметная логика демо-админки пока находится внутри страницы и хранится только в `localStorage`.

## API: NestJS

NestJS выбран как отдельное приложение в том же pnpm workspace: он уже поддерживается доступной версией Node и может обслуживать клиент REST API. Пока реализован только health endpoint.

## База данных

API использует PostgreSQL через Prisma 7 и официальный `@prisma/adapter-pg`, по образцу NVP. `apps/api/prisma/schema.prisma` задаёт начальные модели скутеров, поездок, парковочных зон (GeoJSON Polygon), Tiptap-контента, объявлений, подписок и Top-5 размещений. Prisma-конфиг читает `DATABASE_URL` из окружения.

Подключать сервис следует отдельной базой и пользователем на существующем PostgreSQL сервере. В compose база не запускается и данные текущих проектов не трогаются. Перед миграцией проверьте адрес сервера, TLS, сетевой доступ и резервное копирование. `ContentPage.html` хранит HTML редактора; API должен очищать его по allowlist прежде чем отдавать браузеру.

## Карты и геопозиция

Карта парка использует Google Maps JavaScript API при наличии `VITE_GOOGLE_MAPS_API_KEY`; без ключа включается схематичная интерактивная карта Нячанга. Маркеры, геозоны и демо-координаты сохраняются локально. Обход зоны при завершении поездки проверяется только в клиентском демо: до реального проката это правило нужно перенести в API, вести аудит события и отправлять результат через совместимую телематику. Координаты скутера должны поступать от GPS/телематики, а не от геолокации телефона.

## Контент и платные размещения

Редактор планируется на Tiptap с теми же базовыми расширениями, что используются в NVP: таблицы, ссылки, изображения, выделение и выравнивание. `ContentPage` и `HomePageSettings` дают основу для текстовых страниц и настройки главной. `ListingCategory` разделяет продажу скутеров, аренду скутеров и аренду жилья; `TopPlacement` задаёт позиции витрины, а `Subscription` фиксирует платные размещения жилья и объявлений о продаже байков. UI управления этими сущностями и API ещё предстоит реализовать.

## Окружение и деплой

Фронтенд остаётся в `apps/web`. Workflow GitHub Pages собирает SPA на push в `main`, поддерживает прямые URL через `404.html` и принимает публичные Vite-переменные из GitHub Actions Variables. API собирается в Docker-образ и публикуется в GHCR; при включённом `DO_API_DEPLOY_ENABLED` workflow подключается по SSH к Droplet, применяет Prisma-миграции и перезапускает API за Caddy с HTTPS. PostgreSQL остаётся существующим внешним сервером. Порядок первоначальной настройки описан в [docs/deployment.md](deployment.md).
